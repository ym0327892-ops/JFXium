# JFXium 视图开发规范（下游项目 / AI 必读）

> 本文约定：使用 JFXium 开发业务界面时，**View / ViewModel / Model / App 如何分层、如何命名、如何创建、如何弹窗、如何绑定数据**。
> 适用于任何下游项目，也适用于 AI 生成代码。所有结论以本仓库现有 demo（`jfxium-demo`）与框架源码为准。

---

## 0. 一句话标准

> **View 是无状态的一次性 UI 构建器，随便 `new`；状态放在 ViewModel，用 Property / ObservableList 绑定；App 管窗口与主题；View 不继承原生 `Pane`，要么普通类 + `build()`，要么继承 `VBoxAnt` 系容器。**

---

## 1. 分层与职责

| 层 | 职责 | 禁止 |
|---|---|---|
| **App**（`extends Application`） | 持有 `Stage`、创建 `Scene`、应用/注册主题、页面切换 | 禁止把业务 UI 塞进 App |
| **View** | 构建 UI、收集用户输入、把动作转成对 VM 的调用、显示错误 | 禁止持有 `Stage`；禁止做业务规则；禁止直接访问数据库/网络 |
| **ViewModel** | 持有状态（`Property` / `ObservableList`）、暴露命令方法、业务校验 | **禁止 `import javafx.scene.Node`**；禁止 `new ModalAnt` / 任何弹窗 |
| **Model** | 纯数据（`record` / POJO） | 禁止依赖 UI |

```java
// Model
public record User(long id, String name, String email) {}

// ViewModel
public final class UserListViewModel {
    private final ObservableList<User> users = FXCollections.observableArrayList();
    private final StringProperty keyword = new SimpleStringProperty("");

    public ObservableList<User> users() { return users; }
    public StringProperty keyword() { return keyword; }

    /** 返回错误信息；null 表示成功。VM 不负责弹窗。 */
    public String add(UserDraft draft) {
        if (users.stream().anyMatch(u -> u.name().equals(draft.name()))) {
            return "用户名已存在";
        }
        users.add(new User(nextId(), draft.name(), draft.email()));
        return null;
    }
}
```

## 2. View 的两种形态

### 形态 A：组合式（推荐业务页面）

普通类 + 构造注入依赖 + `build()` 返回 `Node`。

```java
public final class UserListView {

    private final UserListViewModel vm;

    public UserListView(UserListViewModel vm) {
        this.vm = vm != null ? vm : new UserListViewModel();
    }

    /** 只构建 UI；不碰 Stage / Scene / Theme；幂等。 */
    public Node build() {
        InputAnt search = InputAnt.create()
                .placeholder("搜索")
                .bindValue(vm.keyword())
                .build();

        TableView<User> table = TableAnt.<User>create()
                .column("ID", u -> String.valueOf(u.id())).width(60).end()
                .column("姓名", User::name).width(120).end()
                .column("邮箱", User::email).minWidth(220).end()
                .data(vm.users())
                .build();

        ButtonAnt add = ButtonAnt.create("新增")
                .type(ButtonAnt.Type.PRIMARY)
                .onClick(e -> openAddDialog(add))
                .build();

        return CrudTemplate.create()
                .title("用户管理")
                .topLeft(search)
                .topRight(add)
                .body(table)
                .bordered(true)
                .build();
    }

    private void openAddDialog(Node owner) {
        // 见第 6 节
    }
}
```

### 形态 B：继承式（简单页面 / 需要直接当容器用）

类本身就是 Node，**没有 `build()`**。必须继承 `*Ant` 容器，**不要继承原生 `Pane` / `VBox`**。

```java
public final class CenterView extends VBoxAnt {

    public CenterView(UserListViewModel vm) {
        spacing(0);
        background(Background.DEFAULT);
        children(
                PageTemplate.create()
                        .title("控制台")
                        .body(/* Ant 组件 */)
                        .build()
        );
    }
}

// 用法：new CenterView(vm) 直接塞进父容器
```

> 注意：`VBoxAnt` 的链式方法返回 `VBoxAnt` 而非子类。需要协变链式时，继承 `AbstractVBoxAnt<CenterView>`（参考框架内 `BarAnt` 的写法，需 override 相关方法）。
> 一般情况下**优先用形态 A**，继承式只用于“类本身就该是一个容器”的场景。

## 3. 谁 new，谁持 VM

| 场景 | 做法 |
|---|---|
| 页面 / 路由级 | 每次路由 `new XxxView(vm).build()`；View 不做单例 |
| 页面内局部区块 | 不建类，页面内直接用 `VBoxAnt` / `HBoxAnt` / 模板拼 |
| 多处复用 / 有状态 | 才抽成 View 类 |
| 应用壳 | 用 `AppShellAnt` / `WorkspaceTemplate`，不要自己搭 Stage |
| 跨页面共享状态 | 注入**同一个 ViewModel 实例**，而不是把 View 做单例 |

```java
// 路由懒加载：每次进入重新构建，状态干净、无 listener 泄漏
PageRegistry registry = new PageRegistry()
        .register("users", "用户管理", Category.DATA_DISPLAY,
                () -> new UserListView(new UserListViewModel()).build());
```

**原则**：View 无状态、可丢弃、可重建；VM 才是持状态的那一层。

## 5. 数据绑定（MVVM 的核心）

| 控件 | 绑定 API |
|---|---|
| `InputAnt` / `TextAreaAnt` / `SearchInputAnt` | `.bindValue(StringProperty)` |
| `CheckBoxAnt` / `RadioButtonAnt` / `ToggleButtonAnt` | `.bindValue(BooleanProperty)` |
| `ComboBoxAnt` / `ChoiceBoxAnt` | `.bindValue(Property<T>)` |
| `DatePickerAnt` | `.bindValue(ObjectProperty<LocalDate>)` |
| `SpinnerAnt` | `.bindValue(DoubleProperty)` |
| `TableAnt` | `.data(ObservableList<T>)` |

```java
// 双向绑定，View 不持有控件引用取值
StringProperty name = new SimpleStringProperty("");
InputAnt.create().placeholder("姓名").bindValue(name).build();

// ObservableList 变更 → Table 自动刷新，无需手动 refresh
users.add(new User(...));
```

> VM 修改 `ObservableList` / `Property` 必须在 **FX Application Thread**；后台线程取数请 `Platform.runLater(...)`。

## 6. 弹窗 / 新增流程（重点）

### 6.1 边界

- **弹窗是 View 的事**，VM 完全不知道弹窗存在。
- VM 只接收“已校验好的数据”或“业务动作”，返回错误信息，由 View 决定如何显示。

### 6.2 标准写法

```java
private void openAddDialog(Node owner) {
    InputAnt name  = InputAnt.create().placeholder("姓名").build();
    InputAnt email = InputAnt.create().placeholder("邮箱").build();

    // 1. 表单负责收集 + 格式校验
    FormAnt.Result form = FormAnt.create()
            .item("姓名", name, "name").required().end()
            .item("邮箱", email, "email").required().rule(Rule.email()).end()
            .buildResult();

    // 2. 弹窗引用占位，解决“按钮 ↔ Modal”循环引用
    ModalAnt.ModalResult[] ref = new ModalAnt.ModalResult[1];

    ButtonAnt cancel = ButtonAnt.create("取消")
            .onClick(e -> ref[0].close())
            .build();

    ButtonAnt ok = ButtonAnt.create("确定")
            .type(ButtonAnt.Type.PRIMARY)
            .onClick(e -> {
                if (!form.validate()) {          // 校验失败：不关窗
                    return;
                }
                Map<String, Object> v = form.getValues();
                String error = vm.add(new UserDraft(
                        (String) v.get("name"),
                        (String) v.get("email")));   // 交给 VM
                if (error != null) {
                    MessageAnt.error(error);          // 业务错误留在 View 显示
                    return;
                }
                ref[0].close();
            })
            .build();

    HBoxAnt footer = HBoxAnt.create()
            .spacing(8)
            .align(Pos.CENTER_RIGHT)
            .children(cancel, ok);

    ref[0] = ModalAnt.create()
            .title("新增用户")
            .content(form.getRoot())
            .footer(footer)      // 必须自定义 footer
            .build();

    ref[0].open(owner);          // owner 必须是已挂到 Scene 的节点
}
```

### 6.3 关键坑

> `ModalAnt` 的**默认 footer 点“确定”会无条件 `close()`**。
> 要实现“校验失败不关窗”，必须使用 `.footer(...)` 或 `.noFooter()` 自己控制关闭。

### 6.4 校验归属

| 校验类型 | 放哪 | 手段 |
|---|---|---|
| 必填 / 邮箱 / 长度 / 正则 | View 层 | `FormAnt` + `Rule` + `form.validate()` |
| 重名 / 权限 / 后端规则 | ViewModel | 返回错误串或 Result，View 用 `MessageAnt` 显示 |

### 6.5 何时抽独立 Dialog 类

只在**多处复用**时抽：

```java
public final class UserEditorDialog {
    public void open(Node owner, Consumer<UserDraft> onSave) { /* ... */ }
}

// 调用方
new UserEditorDialog().open(add, draft -> {
    String error = vm.add(draft);
    if (error != null) MessageAnt.error(error);
});
```

一次性新增就写在 View 的私有方法里，不要为弹窗单独造一层。

## 7. 命名与文件结构

```text
com.example.app
├── App.java                    // extends Application
├── model/
│   └── User.java               // record
├── viewmodel/
│   └── UserListViewModel.java  // Property / ObservableList / 命令
└── view/
    ├── CenterView.java         // 页面 View
    └── UserEditorDialog.java   // 复用的弹窗 View（可选）
```

约定：

- View 类名以 `View` 结尾；ViewModel 以 `ViewModel` 结尾。
- 包名按 `view` / `viewmodel` / `model` 分开。
- View 的公开入口只有一个：`build()`（形态 A）或构造器（形态 B）。
- 不要定义 `init()` / `initView()` 这类隐式生命周期。需要拆分就用 `private` 方法，只由 `build()` 调用。

---

## 8. 生命周期与线程

1. **`build()` 必须幂等**：重复调用不累积子节点、不重复注册全局 listener。
2. **`build()` 不产生显示副作用**：弹窗要显式 `.open(owner)`。
3. **FX 线程边界**：任何触碰 Scene Graph、`snapshot()`、`Canvas` 的代码必须在 `Platform.isFxApplicationThread()` 为 true 时执行，否则 `Platform.runLater(...)`。
4. **长生命周期组件**若使用 i18n 默认文案，需监听 `Messages.localeProperty()`；一次性弹窗不需要。
5. **释放旧 parent**：替换内容前先把旧节点从父容器移除（JavaFX 单 parent 规则）。

## 9. 红线清单（违反即打回）

| # | 红线 | 正确做法 |
|---|---|---|
| 1 | 业务代码 `new Label/Button/TextField/VBox/HBox/TableView/...` | 统一 `LabelAnt.create(...)` / `ButtonAnt.create(...)` / `VBoxAnt.create(...)` |
| 2 | `setStyle("-fx-...: 颜色/px")` | `styleClass` + 自己的 `.css`；新类名带 `jfx-` 前缀 |
| 3 | CSS 用 `box-shadow` | `-fx-effect: dropshadow(...)` |
| 4 | CSS 用 `:active` / `:focus` | `:pressed`（`:armed`）/ `:focused` |
| 5 | 用 `-fx-transition` 做交互状态 | 直接定义 `:hover` / `:pressed` 状态颜色 |
| 6 | `build()` 返回类型撒谎（弹窗冒充普通节点） | 弹窗返回 Result wrapper（需 `.open()`）；持久节点直接返回 Node |
| 7 | View 里写 `stage.setScene(...)` / 主题切换 | 收到 App 层统一处理 |
| 8 | ViewModel `import javafx.scene.Node` / 创建弹窗 | 弹窗和 Node 只在 View 层 |
| 9 | 给 View 做单例 | View 无状态，每次 `new`；状态放 ViewModel |
| 10 | 直接继承 `Pane` / `VBox` | 继承 `VBoxAnt` / `BorderPaneAnt` / `AbstractVBoxAnt<SELF>` |
| 11 | 在字段初始化时取 i18n 文案 | 字段置 `null`，`build()` 内懒解析 |

## 11. 最小可运行骨架（复制即用）

```java
// ---------- Model ----------
public record User(long id, String name, String email) {}
public record UserDraft(String name, String email) {}

// ---------- ViewModel ----------
public final class UserListViewModel {
    private final ObservableList<User> users = FXCollections.observableArrayList();
    private long seq = 1;

    public ObservableList<User> users() { return users; }

    public String add(UserDraft d) {
        if (d.name() == null || d.name().isBlank()) return "姓名不能为空";
        if (users.stream().anyMatch(u -> u.name().equals(d.name()))) return "用户名已存在";
        users.add(new User(seq++, d.name(), d.email() == null ? "" : d.email()));
        return null;
    }
}

// ---------- View ----------
public final class UserListView {

    public UserListView(UserListViewModel vm) { this.vm = vm; }

    public Node build() {
        TableView<User> table = TableAnt.<User>create()
                .column("ID", u -> String.valueOf(u.id())).width(60).end()
                .column("姓名", User::name).width(140).end()
                .column("邮箱", User::email).minWidth(220).end()
                .data(vm.users())
                .build();

        ButtonAnt add = ButtonAnt.create("新增")
                .type(ButtonAnt.Type.PRIMARY)
                .onClick(e -> openAddDialog(add))
                .build();

        return CrudTemplate.create()
                .title("用户管理")
                .topRight(add)
                .body(table)
                .bordered(true)
                .build();
    }

    private void openAddDialog(Node owner) {
        InputAnt name  = InputAnt.create().placeholder("姓名").build();
        InputAnt email = InputAnt.create().placeholder("邮箱").build();

        FormAnt.Result form = FormAnt.create()
                .item("姓名", name, "name").required().end()
                .item("邮箱", email, "email").rule(Rule.email()).end()
                .buildResult();

        ModalAnt.ModalResult[] ref = new ModalAnt.ModalResult[1];

        ButtonAnt cancel = ButtonAnt.create("取消")
                .onClick(e -> ref[0].close()).build();

        ButtonAnt ok = ButtonAnt.create("确定")
                .type(ButtonAnt.Type.PRIMARY)
                .onClick(e -> {
                    if (!form.validate()) return;

                            (String) v.get("name"), (String) v.get("email")));
                    if (err != null) { MessageAnt.error(err); return; }

        ref[0] = ModalAnt.create()
                .title("新增用户")
                .content(form.getRoot())

}
```

## 12. Tabs 多子页设计（TabPane + 独立子 View）

### 12.1 定位

**Tab 是页面内的局部切换，不是路由。** 不要为每个 tab 注册 `PageRegistry`，除非需要 URL/深链。

```
UserDetailView（父页面，持有 TabsAnt）
├── BasicInfoTabView   → 基本信息
├── LogsTabView        → 操作日志
└── SettingsTabView    → 设置
```

- 父 View **只负责装配 tab 和切换逻辑**，不写子页业务。
- 子 tab View 遵循第 2 节：普通类 + `build()`，或继承 `VBoxAnt`。
- 子 View **不知道 TabsAnt 的存在**，禁止调用 `TabsAnt.controllerOf(...)`。

### 12.2 目录与 VM 拆分

```text
view/
├── UserDetailView.java          // 父：装配 TabsAnt
└── tab/
    ├── BasicInfoTabView.java
    ├── LogsTabView.java
    └── SettingsTabView.java
viewmodel/
├── UserDetailViewModel.java     // 共享上下文（userId / 当前 User）
└── tab/
    ├── LogsViewModel.java       // 独立状态（分页 / 筛选）
    └── SettingsViewModel.java   // 独立状态（表单草稿）
```

| 状态类型 | 放哪 |
|---|---|
| 跨 tab 共享（当前用户、详情数据） | 父 `UserDetailViewModel`，注入给各子 View / 子 VM |
| 单个 tab 私有（日志分页、设置草稿） | 该 tab 自己的 VM |
| 跨 tab 通信 | 监听父 VM 的 `Property`，或 EventBus；**禁止子 View 互相持有引用** |

### 12.3 三种构建策略

| 策略 | 适用 | 代价 |
|---|---|---|
| **Eager 全建** | tab 少（≤3）、内容轻 | 启动即建全部节点，内存高但切换最快 |
| **Lazy 懒建 + 缓存**（推荐） | tab 多、内容重 | 首次进入才建；之后保留状态 |
| **每次切换重建** | 要求每次进入状态干净 | 每次都丢状态，构建开销大 |

> `TabsAnt` 的 `tab(key, label, content)` 接收的是**已构建的 Node**，没有内置懒加载。
> 懒加载用「占位容器 + `onChange` 首次填充」实现。
> `TabsAnt` 的内容区是 `StackPane`，切换只改 `visible/managed`，**节点不会被移除**，因此已建 tab 的状态默认保留。

### 12.4 Eager 写法（简单场景）

```java
public Node build() {
    return TabsAnt.create()
            .type(TabsAnt.Type.LINE)
            .tab("basic", "基本信息", new BasicInfoTabView(vm).build())
            .tab("logs", "操作日志", new LogsTabView(new LogsViewModel(vm.userId())).build())
            .tab("settings", "设置", new SettingsTabView(vm).build())
            .build();
}
```

### 12.5 Lazy 写法（推荐）

```java
public final class UserDetailView {

    private final UserDetailViewModel vm;

    public UserDetailView(UserDetailViewModel vm) { this.vm = vm; }

    public Node build() {
        // 1. key → 懒加载工厂（此时不执行）
        LinkedHashMap<String, Supplier<Node>> factories = new LinkedHashMap<>();
        factories.put("basic",    () -> new BasicInfoTabView(vm).build());
        factories.put("logs",     () -> new LogsTabView(new LogsViewModel(vm.userId())).build());
        factories.put("settings", () -> new SettingsTabView(vm).build());

        // 2. key → 占位容器（TabsAnt 必须拿到 Node）
        Map<String, StackPaneAnt> hosts = new LinkedHashMap<>();
        Set<String> loaded = new HashSet<>();

        // 3. 首次激活才构建；loaded 保证只建一次
        Consumer<String> ensureLoaded = key -> {
            if (key == null || !factories.containsKey(key) || !loaded.add(key)) {
                return;
            }
            hosts.get(key).getChildren().setAll(factories.get(key).get());
        };

        // 4. 组装 TabsAnt（onChange 在 build 前注册）
        TabsAnt.Builder tabs = TabsAnt.create()
                .type(TabsAnt.Type.LINE)
                .activeKey("basic")
                .onChange(ensureLoaded);

        for (String key : factories.keySet()) {
            StackPaneAnt host = StackPaneAnt.create();
            hosts.put(key, host);
            tabs.tab(key, titleOf(key), host);
        }

        Node root = tabs.build();

        // 5. 初始 tab 不会触发 onChange —— 必须手动初始化一次
        ensureLoaded.accept(TabsAnt.controllerOf(root).getCurrentKey());
        return root;
    }

    private String titleOf(String key) {
        return switch (key) {
            case "basic" -> "基本信息";
            case "logs" -> "操作日志";
            case "settings" -> "设置";
            default -> key;
        };
    }
}
```

### 12.6 每次切换重建（不保留状态）

```java
Consumer<String> rebuild = key -> {
    if (key == null || !factories.containsKey(key)) return;
    hosts.get(key).getChildren().setAll(factories.get(key).get());
};
```

> 只改 `onChange` 回调，其余结构不变；不要缓存 `loaded`。

### 12.8 生命周期

- tab 内的长生命周期资源（EventBus 订阅、`Messages.localeProperty()` 监听、定时器）必须在页面销毁时释放。
- 约定给父 View（或子 tab View）提供 `dispose()`，由路由/App 在切走时调用。
- 只挂在节点树上的 listener 会随节点不可达被 GC，无需手动处理。

### 12.9 动态增删 / 可关闭 / 右侧操作菜单

`TabsAnt.Controller` 现在支持运行时增删改，**不需要重建整棵 TabsAnt**：

| API | 说明 |
|---|---|
| `addTab(key, label, content[, disabled, closable])` | 追加 tab；key 为空或重复返回 `false` |
| `removeTab(key)` / `removeTab(index)` / `removeAllTabs()` | 程序化移除（不触发 `onClose`） |
| `updateTab(key, label, content)` / `setTabLabel` / `setTabContent` | 更新标题或内容 |
| `setTabDisabled(key, b)` / `setTabClosable(key, b)` | 运行时切换禁用 / 可关闭 |
| `closeTab(key)` / `closeCurrent()` / `closeOthers(keepKey)` / `closeAll()` | **用户语义关闭**：尊重 `closable` + `onBeforeClose`，触发 `onClose` |

#### 可关闭 tab（×）

```java
Node tabs = TabsAnt.create()
        .closable(true)                       // 所有 tab 默认带 ×
        .tab("a", "A", a)
        .tab("b", "B", b, false, false)       // 单独关闭该 tab 的 ×
        .onBeforeClose(key -> canClose(key))  // 返回 false 阻止关闭
        .onClose(key -> cleanup(key))         // 关闭完成后通知
        .build();

TabsAnt.Controller ctrl = TabsAnt.controllerOf(tabs);
ctrl.closeTab("a");        // 用户语义
ctrl.removeTab("b");       // 程序化，不触发 onClose
```

- × 按钮使用 `A11y.FirePane`：鼠标 / 键盘空格回车 / 读屏 FIRE 三路一致。
- `onClose` **只**由 `closeTab / closeCurrent / closeOthers / closeAll` 触发；`removeTab` 不触发。
- `closeAll()` 只关闭 `closable=true` 的 tab；要强制清空用 `removeAllTabs()`。

#### 右侧「标签操作」菜单

默认在标签栏最右侧渲染一个操作按钮（`overflowMenu(true)`）：

- 列出当前所有 tab，点击直接切换（tab 溢出时也能访问到）
- 关闭当前 / 关闭其他 / 关闭全部（无可关闭 tab 时对应项禁用）

```java
TabsAnt.create()
        .overflowMenu(true)          // 默认 true；false 隐藏整个右侧菜单
        .showCloseCurrent(true)      // 单独控制「关闭当前」是否显示
        .showCloseOthers(true)       // 单独控制「关闭其他」是否显示
        .showCloseAll(true)          // 单独控制「关闭全部」是否显示
        .closable(true)              // 控制 × 是否渲染；单个 tab 用 5 参 tab(...) 覆盖
        .tab("a", "A", a)
        .build();
```

> 单个 tab 的可关闭性：`.tab(key, label, content, disabled, closable)`；全局默认用 `.closable(boolean)`。
> 右侧菜单的显示：`.overflowMenu(false)` 整体隐藏；三个 `showClose*` 控制具体关闭项。

#### 限制与反模式

| 限制 / 反模式 | 说明 |
|---|---|
| 误以为有 `TabPaneAnt` | 框架**没有** `TabPaneAnt`。原生 `.tab-pane` 只有 LESS 样式增强、没有 Ant 封装，按红线 #11 业务代码也不能 `new TabPane()` |
| 需要竖向标签导航 | `TabsAnt` 只支持 TOP / BOTTOM 横向标签（LEFT/RIGHT 已移除）。竖向导航用 `MenuAnt` / `AppShellAnt` 的 sider |
| 把所有 tab 塞进一个巨型 View / 一个巨型 VM | 按 tab 拆 View 和 VM，父层只装配 |
| 子 tab View 里 `TabsAnt.controllerOf(...)` | 子页不应感知 tab 容器；切换由父层做 |
| 每次 `build()` 都重新 `new` 子 View 还注册全局监听 | 会导致监听累积；要么缓存，要么提供 `dispose()` |
| 把 tab 当路由注册 | tab 是局部切换；需要深链才在路由层解析 tabKey |
