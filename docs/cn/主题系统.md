# JFXium 主题系统

JFXium 使用 LESS 预处理器管理主题，**内置 11 套主题入口 / 6 个 `Theme` 类**：Ant Design 系（Light/Dark/Custom/Tool）+ Fluent 2 系（Fluent/Fluent Dark），以及各自的 compact 密度变体（`CustomTheme` 模板另有独立紧凑入口）。

## 主题文件位置

```
src/main/resources/org/openkawu/jfxium/css/
├── less/                          # LESS 源文件
│   ├── variables-base.less        # 共享尺寸/间距/字体/mixin
│   ├── palette-light.less         # 亮色配色单一来源（纯颜色 + 动效令牌）
│   ├── palette-dark.less          # 暗色配色单一来源
│   ├── palette-custom.less        # 自定义（企业紫）配色单一来源
│   ├── palette-fluent.less        # Fluent 亮色配色（WinUI 3 桌面口径，强调填充 #0067c0）
│   ├── palette-fluent-dark.less   # Fluent 暗色配色（强调填充亮青 #4cc2ff）
│   ├── variables.less             # 组装：variables-base + palette-light
│   ├── variables-dark.less        # 组装：variables-base + palette-dark
│   ├── theme-base.less            # 全部组件样式（主题无关）
│   ├── theme-light.less           # 亮色主题入口
│   ├── theme-dark.less            # 暗色主题入口
│   ├── theme-light-tool.less      # 工具主题入口（字号不缩、行高压薄的紧凑工具列）
│   ├── theme-custom.less          # 自定义主题模板（企业紫示例）
│   ├── theme-custom-compact.less  # 自定义模板的紧凑版
│   ├── theme-fluent.less          # Fluent 2 亮色主题入口
│   ├── theme-fluent-compact.less  # Fluent 2 亮色紧凑入口
│   ├── theme-fluent-dark.less     # Fluent 2 暗色主题入口
│   ├── theme-fluent-dark-compact.less  # Fluent 2 暗色紧凑入口
│   └── theme-*.css                    # 编译产物（generate-resources 阶段由 jlessc 纯 Java 编译生成，无需 Node.js）
```

> **构建依赖**：LESS 编译使用 **jlessc**（纯 Java LESS 编译器），通过 `groovy-maven-plugin` 在 `generate-resources` 阶段自动执行，**无需 Node.js**。运行 `mvn compile` 或 `mvn install` 即可自动编译。

## 内置主题清单

| 主题入口 | Java 类 | 适用场景 |
|------|---------|---------|
| **light** | `LightTheme` | 默认亮色主题，类 GitHub 风格 |
| **dark** | `DarkTheme` | 默认暗色主题 |
| **custom** | `CustomTheme` | 自定义主题模板（可复制改色阶派生新主题） |
| **tool** | `ToolTheme` | 工具主题：紧凑工具列密度变体，字号不缩、行高压薄、cell padding 打薄，模拟 IntelliJ/DBeaver 观感 |
| **fluent** | `FluentTheme` | 微软 Fluent（Windows 11 / WinUI 3 桌面口径）亮色，强调填充 `#0067c0`，圆角 4px，Segoe 系字号阶梯，动效 100/200/300ms |
| **fluent-dark** | `FluentDarkTheme` | 微软 Fluent 暗色，强调填充提亮为亮青 `#4cc2ff`（暗底品牌色），中性分层 `#2c2c2c > #282828 > #202020 > #1c1c1c` |

> `light-compact` / `dark-compact` / `custom-compact` / `fluent-compact` / `fluent-dark-compact` 属于密度变体，由 `ThemeManager.setDensity(ThemeDensity)` 独立控制，不单独提供 `Theme` 类。

> 其中 `light` / `dark` 参与 `ThemeManager` 的 dark 状态机；`custom` 为自定义主题模板，`CustomTheme` 支持密度派生（COMPACT → `theme-custom-compact.css`）但无 dark 变体，可 `applyTheme(new CustomTheme())` 或按需追加对应 CSS 资源；`tool` 配色与 Light 一致，仅覆盖尺寸 token，自身已是紧凑档，不参与密度派生与 dark 轴。

> `fluent` / `fluent-dark` 组成 `ThemeManager.Family.FLUENT` 家族，参与 dark 状态机（选中 Fluent 后 `setDark(true)` → Fluent Dark，不会回退到 Ant 系）。二者 **accent 固定为 WinUI 3 强调色阶**（亮 `#0067c0` / 暗提亮 `#4cc2ff`）：`Theme.hasFixedAccent()` 返回 `true`，`ThemeManager` 不再注入运行时主色，避免被通用预设蓝覆盖（见 BUG #177）；若要换色须自备整套 Fluent 色相（`ThemeColor.generateColorScale()` 产不出）。

## 切换主题

```java
import org.openkawu.jfxium.core.theme.*;

ThemeManager themeManager = ThemeManager.getInstance();

// 方式一：切换到指定主题
themeManager.applyTheme(new DarkTheme());           // 深色主题

// 密度与主题正交：setDensity 不改变当前主题
themeManager.setDensity(ThemeDensity.DEFAULT);      // 默认密度（宽松）
themeManager.setDensity(ThemeDensity.COMPACT);      // 紧凑密度（减间距 / 控件高）

// 方式二：快捷切换
themeManager.toggleTheme();        // 亮/暗切换

// 方式三：动态修改主题色（无需重新编译 CSS）
themeManager.setPrimaryColor("#ff6b6b");                    // 自定义颜色
themeManager.setPrimaryColor(ThemeColor.Preset.PURPLE);     // 预设颜色

// 方式四：切换到 Fluent 2（Windows 11 / WinUI 3 风格）
themeManager.applyTheme(new FluentTheme());         // Fluent 亮色
themeManager.applyTheme(new FluentDarkTheme());     // Fluent 暗色
// 也可用家族轴切换（dark 轴会跟着走）：
themeManager.setFamily(ThemeManager.Family.FLUENT);
themeManager.setDark(true);                         // → Fluent Dark（不会回退到 Ant）

// 读当前状态（状态卡 / 设置页用）
themeManager.getActiveThemeName();                  // "JFXium Fluent" / "JFXium Fluent Dark" ...
themeManager.getCurrentTheme().hasFixedAccent();    // Fluent 系为 true：主色注入被跳过，保留品牌蓝
```

> **Fluent 系的 accent 是固定的**：其 CSS 已定义完整且自洽的 10 档 + 语义槽色阶，
> `hasFixedAccent()` 返回 `true` 时 `ThemeManager` 不再注入运行时主色（否则会被通用预设蓝
> `#1677ff` 覆盖，见 BUG #177）。需要换主色的主题请自行提供整套色阶，并在 `Theme` 实现里返回 `false`。

**ThemeManager 核心 API：**

| 方法 | 说明 |
|------|------|
| `applyTheme(Theme)` | 应用指定主题 |
| `setDark(boolean)` | 直接指定亮/暗轴 |
| `setDensity(ThemeDensity)` | 独立设置密度（DEFAULT / COMPACT，不影响当前主题） |
| `getDensity()` | 获取当前生效的密度 |
| `toggleTheme()` | 亮/暗主题切换 |
| `setPrimaryColor(String)` | 动态修改主题色（运行时生效） |
| `setPrimaryColor(ThemeColor.Preset)` | 用预设色板修改主题色 |
| `registerScene(Scene)` | 注册 Scene 以支持动态主题切换 |
| `registerRegion(Region)` | 注册独立 Region（如 Popup 内容）跟随主题 |
| `getCurrentTheme()` | 获取当前主题对象 |
| `isDark()` | 判断当前是否为暗色 |
| `setFamily(ThemeManager.Family)` | 切换设计风格家族（`ANT_DESIGN` / `FLUENT`），明暗 / 密度 / 主色语义保持不变 |
| `getCurrentFamily()` | 获取当前家族（对 Fluent 主题不再误报为 Ant Design） |
| `getActiveThemeName()` | 当前生效主题的展示名（取自 `Theme.getName()`，状态卡 / 设置页首选） |
| `getCurrentThemeFamily()` | 遗留方法（已 `@Deprecated`），改用上面两个 |

## 密度切换（§15.6 落地）

> 自 §15.3 P3 起，密度（DEFAULT / COMPACT）作为正交维度独立于「家族 × 暗色」主题之外，
> 不再为每种密度派生子类（如 `LightCompactTheme`）。切换密度的唯一入口是
> `ThemeManager.setDensity(ThemeDensity)`。

### 为什么需要正交维度

旧的 2×2×2 笛卡尔积方案（4 个 `*CompactTheme` 类）有两个痛点：

1. **组合爆炸** — 每新增一个 family（如自定义模板）就要多写 compact 变体
2. **正交性违反** — 切换主色或切到暗色时需要重新指定 compact 变体，状态机变得复杂

正交拆分后，状态机降到 2D（family × dark），密度作为旁路状态独立维护，互不干扰：

```
主题 = family × dark                // 走 applyTheme(Theme)
密度 = DEFAULT | COMPACT            // 走 setDensity(ThemeDensity) —— 正交
```

### API 用法

```java
import org.openkawu.jfxium.core.theme.ThemeDensity;
import org.openkawu.jfxium.core.theme.ThemeManager;

ThemeManager tm = ThemeManager.getInstance();

// 应用主题（密度与主题正交，互不影响）
tm.applyTheme(new LightTheme());           // 亮色 + Default 密度
tm.setDensity(ThemeDensity.COMPACT);       // 立即切换为紧凑密度

// 读取当前密度
ThemeDensity current = tm.getDensity();    // DEFAULT / COMPACT

// 切换 Demo 推荐写法
tm.setDensity(tm.getDensity() == ThemeDensity.DEFAULT
        ? ThemeDensity.COMPACT
        : ThemeDensity.DEFAULT);
```

### 底层机制

`setDensity(ThemeDensity)` 内部走两步（`buildDensityCss()` + `applyDensityToAll()`）：

1. **构造 density CSS 变量串** — 用 Java 21 text block 拼出所有 `-control-height` / `-spacing-*` / `-table-*-height` 的 looked-up color 声明
2. **data-URI 注入到所有已注册 Scene** — 复用 M19.51 走通的安全注入路径，把变量串作为临时 stylesheet 加到 `scene.getStylesheets()` 末尾，CSS 变量自动级联覆盖现有 token

兜底机制：2 个 `theme-*-compact.css`（light-compact / dark-compact）仍然由 `jlessc` 编译产物保留，
仅作为「万一 P2 注入失败时降级」的安全网，Java 代码不再引用（spec §15.5.1 短期方案）。

## 自定义主题

JFXium 的主题系统参考 Ant Design 设计，**只需修改一个 LESS 文件即可生成整套 UI 主题**。

### 主题文件结构

```
css/less/
├── variables-base.less      # 基础尺寸、间距（一般不需要修改）
├── palette-light.less       # 亮色配色单一来源
├── palette-dark.less        # 深色配色单一来源
├── palette-custom.less      # 自定义（企业紫）配色单一来源
├── variables.less           # 组装：variables-base + palette-light
├── variables-dark.less      # 组装：variables-base + palette-dark
├── theme-base.less          # 组件样式（使用变量，不需要修改）
├── theme-light.less         # 浅色主题入口
├── theme-dark.less          # 深色主题入口
├── theme-light-tool.less    # 工具主题入口（尺寸 token 覆盖）
└── theme-custom.less        # ← 自定义主题示例
```

> 配色与尺寸分离：**改配色只动 `palette-*.less`**（纯颜色 + 动效令牌，不 import `variables-base`，
> 因此不会反向覆盖紧凑主题刚设好的尺寸覆盖）；`variables*.less` 只做「尺寸 + 配色」组装。

### 方式一：复制修改 theme-custom.less（推荐）

**只需 3 步：**

#### 第 1 步：复制配色文件

```bash
# 复制调色板（配色单一来源），命名随意
cp css/less/palette-custom.less css/less/palette-mytheme.less
```

#### 第 2 步：修改颜色变量

编辑 `palette-mytheme.less`，修改颜色值：

```less
// 主题色 - 改为红色
@color-accent-5: #f5222d;
@color-accent-6: #cf1322;

// 成功色 - 改为绿色
@color-success-5: #52c41a;

// 背景色 - 改为浅灰
@color-bg-subtle: #f5f5f5;

// 边框色
@color-border-default: #d9d9d9;

// ... 其他色阶与语义色（0-9 色阶 + fg/bg/border/状态色五档）
```

#### 第 3 步：新建入口并发起编译

```less
// theme-mytheme.less
@import "variables-base.less";   // 尺寸
@import "palette-mytheme.less";  // 你的配色（纯颜色，不含尺寸）
@import "theme-base.less";       // 组件样式（必须保留）
```

#### 第 3 步：编译生成 CSS

**手动编译（使用 jlessc）：**
```bash
# jlessc 通过 Maven 插件自动执行，无需手动调用
# 如需单独编译某个主题，可通过 ./mvnw compile 触发
# 注意：macOS / Windows 下的“没有 maven”只需用仓库自带 wrapper，无需另装 CLI
./mvnw compile -pl jfxium
```

**自动编译（推荐）：**
编辑 `jfxium/pom.xml`，在 groovy-maven-plugin 的 `themes` 列表中添加你的主题名：

```groovy
def themes = [
    'theme-light', 'theme-dark',
    'theme-custom', 'theme-custom-compact',
    'theme-light-compact', 'theme-dark-compact',
    'theme-mytheme'   // ← 新增你的主题
]
```

然后运行：
```bash
./mvnw compile
```

#### 使用自定义主题

给自己的主题建一个类实现 `Theme`（照抄框架的 `CustomTheme` 即可），再用同一入口挂上。

> **CSS 放谁的模块里很关键**：`getUserAgentStylesheet()` 里的 `getClass().getResource(...)`
> 是**在框架侧**执行的，所以内置主题读框架自己的 CSS 没问题。你的主题若把 CSS 放在**你自己的模块**里
> （`src/main/resources/mytheme/brand.css` 之类），同样能读到 —— 实测 module-path 下正常。
> 但**反向不行**：你的模块读不到框架模块里的 CSS，这正是下面那条 ⚠️ 的由来。

```java
public class MyTheme implements Theme {
    @Override public String getName() { return "My Theme"; }
    @Override public String getUserAgentStylesheet() {
        // ⚠️ 这里必须是「你自己的主题 CSS」：或放在你自己的模块（/mytheme/mytheme.css），
        //    或由框架编译产出（CustomTheme 用的就是 /org/openkawu/jfxium/css/theme-custom.css）。
        //    写成 "/org/openkawu/jfxium/css/theme-mytheme.css" 而文件不存在 →
        //    requireNonNull 直接 NPE（框架 css 目录只有内置主题那几个文件）。
        return Objects.requireNonNull(
            getClass().getResource("/mytheme/mytheme.css")
        ).toExternalForm();
    }
    @Override public ThemeType getType() { return ThemeType.LIGHT; }
}

// 和内置主题完全一样的用法（全局，支持密度/主题色联动）
ThemeManager.getInstance().applyTheme(new MyTheme());
```

> ⚠️ **别写成 `scene.getStylesheets().add(getClass().getResource("…/theme-mytheme.css"))`**。
> JFXium 是**命名模块**：你的模块在 module-path 下**读不到框架模块里的资源**，那行会
> 在运行期 NPE（实测：module-path → `Class.getResource` 返回 null；纯 classpath 才侥幸能跑）。
> 正确做法是**让框架自己去定位 CSS** —— `Theme` 接口的 `getUserAgentStylesheet()` 在框架侧调用，
> `applyTheme()` 再由 `Application.setUserAgentStylesheet` 全局挂载。
> 只有当你**不打算用 ThemeManager**（脱管主题，如 shadcn 风格完全自绘）时，才考虑直接挂
> Scene 样式表 —— 代价是丢掉了主题切换/密度/主题色联动。

### 方式二：运行时动态修改主题色

使用 ThemeManager 动态修改主题色，无需重新编译 CSS：

```java
ThemeManager themeManager = ThemeManager.getInstance();

// 修改主题色为自定义颜色
themeManager.setPrimaryColor("#ff6b6b");

// 或使用预设颜色
themeManager.setPrimaryColor(ThemeColor.Preset.RED);
themeManager.setPrimaryColor(ThemeColor.Preset.PURPLE);
themeManager.setPrimaryColor(ThemeColor.Preset.GREEN);
```

### 方式三：覆盖特定组件样式

> ⚠️ 红线 #1：禁止用 `style()` / `setStyle()` 写死颜色。正确做法是挂自定义 styleClass，把颜色写进你的 LESS/CSS：

```java
Button btn = ButtonAnt.create("自定义")
    .styleClass("my-brand-btn")     // 挂自定义类
    .build();
```

```less
/* 你的样式文件 */
.my-brand-btn {
  -fx-background-color: @color-danger-5;   // 用 token，不写死色值
  -fx-text-fill: white;
}
```

> **图表色板说明**：`@color-chart-1..8` 定义在 `variables-base.less`（全部主题入口共用），
> 采用 Ant Design 官方数据可视化分类色板（AntV category10）前 8 色。
> 明暗主题**共用同一套色板**（与 modena / AtlantaFX 口径一致）——
> 定性色板的语义是「哪条数据是哪条」，换板会让用户丢失视觉记忆。
> 每个色另有 `@color-chart-N-alpha20`（面积图填充）/ `-alpha70`（气泡）派生。
> 对应的 CSS 查找色为 `-color-chart-1..8`（含两个 alpha 变体），可直接在
> `-fx-background-color` / `-fx-stroke` / `-fx-fill` 中使用。

### 与 Ant Design 主题编辑器对比

## 背景分层（统一口径）

JFXium 的常用背景分成 4 层。**基础布局容器默认透明**，只负责排布；真正的视觉底色由 `Background` 枚举对应的背景层级承担。

### 四层速查表

| Background 枚举 | CSS Token | Light 色值 | 用途 | 典型组件 |
|---|---|---|---|---|
| `Background.TRANSPARENT` | `transparent` | `transparent` | 只负责排布，不负责画底色 | `HBoxAnt` / `VBoxAnt` / `HBarAnt` / `VBarAnt` |
| `Background.LAYOUT` | `-color-bg-layout` | `#f0f2f5` | 页面最外层底色（灰底） | AppShell 外围、页面骨架、滚动容器外框 |
| `Background.SUBTLE` | `-color-bg-subtle` | `#f6f8fa` | 次区域底色（Sider、标题条、次级分区） | Sider、标题条、卡片头部 |
| `Background.DEFAULT` | `-color-bg-default` | `#ffffff` | 内容主体白底 | 表单、列表、详情卡片、主内容区 |

### 记忆口诀

- **TRANSPARENT**：只排版，不画底色
- **LAYOUT**：页面最外层灰底
- **SUBTLE**：侧栏 / 标题条 / 次级区域
- **DEFAULT**：内容主体白底

> 这 4 层和 [最佳实践](./最佳实践.md#7-页面背景色分层) 保持同一套口径。

## styleClass 体系

> 自 2026-05-17 重构后，JFXium 全部组件采用"styleClass + LESS"模式管理视觉样式，
> **不再使用 inline `setStyle("-fx-...")` 拼字符串**。本节说明如何利用这套体系做自定义。

### 设计原则

1. **Java 端只挂 styleClass，不写 inline 样式**——颜色、字号、字重、边框全部交给 LESS 选择器
2. **每个组件都有基础类 + 修饰类**——状态/尺寸/类型通过修饰类切换，不在 Java 里拼字符串
3. **通用模式抽公共选择器**——例如所有"浮窗菜单"（Dropdown / AutoComplete / Mentions / TreeSelect）共用 `.jfx-popup-menu`，所有"遮罩面板"（Drawer / Modal）共用 `.jfx-overlay-*`

### 使用方法

#### 1. 给组件挂自定义 styleClass

所有 *Ant 组件都提供 `.styleClass(String)` 方法（基于 `AbstractStyleBuilder`）：

```java
Button btn = ButtonAnt.create("自定义")
    .type(ButtonAnt.Type.PRIMARY)
    .styleClass("my-action-btn")        // 挂自定义类
    .styleClass("compact")              // 可多次叠加
    .build();
```

然后在你的 LESS / CSS 里写规则：

```less
.my-action-btn {
  -fx-pref-width: 120px;
  -fx-font-weight: 600;
}

.my-action-btn.compact {
  -fx-padding: 4 8 4 8;
}
```

#### 2. 利用内置 styleClass 自定义状态

JFXium 组件的状态都通过修饰类暴露。你可以用 LESS 覆盖：

```less
/* 自定义"危险按钮"hover 时的颜色 */
.button.danger:hover {
  -fx-background-color: #ff4d4f;  /* 覆盖默认的 -color-danger-hover */
}

/* 自定义"选中行"背景 */
.table-row-cell:selected {
  -fx-background-color: -color-warning-subtle;  /* 改成黄色调 */
}

/* 给所有 Alert 加阴影 —— 用阶梯 mixin，色随明暗翻转；
   手写 rgba 会在深色主题下与背景同黑（浮层感丢失） */
.jfx-alert {
  .shadow-elev-16();
}
```

### 常见 styleClass 命名约定

| 前缀模式 | 含义 | 示例 |
|---------|------|------|
| `jfx-<component>` | 组件根容器 | `.jfx-alert`、`.jfx-popup-menu` |
| `<component>-<part>` | 组件子节点 | `.alert-title`、`.collapse-arrow` |
| `<component>-<state>` | 状态修饰类 | `.alert-success`、`.steps-current` |
| `<size>` | 尺寸修饰类 | `.size-small`、`.size-large` |
| `:hover` / `:focused` / `:armed` / `:pressed` | JavaFX 伪类 | `.button:hover` |

完整常量定义见 `org.openkawu.jfxium.core.style.JfxStyles`。

## 自定义组件

> 想写自己的 \*Ant 组件？继承 `AbstractStyleBuilder` 即可享受统一的 style/styleClass API。

### AbstractStyleBuilder 公共基类

每个 *Ant Builder 都有 `.style(String)` 和 `.styleClass(String)` 两个钩子。
这些行为统一在 `core/builder/AbstractStyleBuilder<SELF>`，使用 self-bounded 泛型保证链式 API 类型正确：

```java
package com.myapp.component;   // 你自己的业务包

// === 1. 先在 JfxStyles.java 登记常量（加 jfx- 前缀避免与 modena 冲突，红线 #8） ===
// public static final String JFX_MY_PANEL = "jfx-my-panel";

public class MyPanelAnt {

    public static Builder create() {
        return new Builder();
    }

    public static class Builder extends AbstractStyleBuilder<Builder> {
        private String title = "";

        public Builder title(String title) {
            this.title = title;
            return this;
        }

        public VBox build() {
            VBox panel = new VBox();                                        // 框架内部实现，红线 #11 豁免
            panel.getStyleClass().add(JfxStyles.JFX_MY_PANEL);              // 挂内置类（jfx- 前缀）
            // ... 组装内部节点 ...

            applyStyles(panel);                                             // 应用用户的 style/styleClass
            return panel;
        }
    }
}
```

继承后你的 Builder 自动拥有：
- `style(String)` —— 设置 inline 样式（慎用）
- `styleClass(String)` —— 追加额外 styleClass（推荐）
- `applyStyles(Node)` —— 在 build() 末尾调用，把累积的钩子应用到目标节点

### 关键约定

1. **build() 末尾调用 `applyStyles(node)`**：让用户的 `.style/.styleClass` 在内置 styleClass **之后** 应用，确保用户能覆盖默认样式
2. **结构性属性留 Java**：例如 `setPrefSize(...)`、padding 与 level 联动这种动态值，无法在 LESS 表达
3. **视觉性属性走 LESS**：颜色、字号、字重、边框、圆角、阴影一律下沉到 LESS 选择器
4. **状态机用修饰类**：例如 `success/warning/error` 切换不要在 Java 里拼颜色，用 styleClass 切换让 LESS 选择器接管
